# C++ 参照の検索(cxxref)

C++ のリポジトリでは、clang(libtooling)で全 TU を解析した参照索引(リポジトリのルートの `.index`)を、MCP サーバー `code-ref-index` のツールで引けます。

- 使う場面: C++ の関数・型・変数が「どこで使われているか・どこから呼ばれているか」を知る必要があるとき(引数を変える前の呼び出し元の洗い出し、変更の影響の調査、使っている箇所の質問)。このときは、ソースを grep する前に `refs` を呼びます
- 使わない場面: ファイルや関数の説明、場所の分かっている箇所の修正、ログやテストの追加など、使われている場所の一覧が要らない作業。C++ でないリポジトリ
- `refs`(引数 `name` は修飾名か、その末尾)は、1 回で次を返します。各行には、ファイルと行、その行の本文が付きます
  - `calls`: clang が解決した呼び出し。どの関数の中に書かれているか(`[in ...]`)付き。そのまま答えに使えます。同じ名前を rg でソースから取り直して確かめる必要はありません
  - `other references`: 関数ポインターの取得、テンプレート引数などの呼び出し以外の参照
  - `definitions and declarations`: 定義と宣言
  - `unresolved template calls (dep)`: テンプレート内で解決先が決まらない同名の呼び出し。注記とソース行から、呼び出し先を自分で判断してください
  - `text matches ... not in the index`: ソースの同名の一致のうち、索引に無いものとその理由(コメント内・無効な `#if`・マクロ定義・文字列・解析されていないファイル)。「コメント内」とされた一致は答えに含めません
- 呼び出し側を直すときは、`calls` の行の前後だけを開いて直します。直した後の確かめに `refs` を呼び直さないでください(直後は索引の作り直しが裏で走り、結果は前の索引の行を当て直したものです)。確かめは rg で足ります
- `refs` と `check` の引数 `root` には、作業中のフォルダの絶対パスを渡してください(サーバーはプラグインの場所で動くことがあります)
- `check`(引数 `locations` は `path:line` の配列)は、その行が索引でどう扱われているかを返します。rg などで見つけた行を答えに入れるか迷ったときに使います
- 索引が無い(`index not found`)と返ってきたら、そのリポジトリではふだんどおり rg などで探してください。索引の作り方は返ってきたメッセージにあります。作るのは時間がかかるので、作るかどうかはユーザーに確かめてください
