# cxxref のベンチマーク

cxxref を入れると、Copilot が C++ の作業をするときに、何が変わるのか、変わらないのかをまとめた資料です。導入するかどうかを決めるために、問題文・渡した指示・エージェントの動き・結果を、悪い結果も含めてそのまま載せます。

- コードベース A は、名前を伏せた C++ のゲームエンジンです(367 TU)。名前と、記号・マクロの名前の接頭辞(`a::`・`A_`)は伏せて書きます。問題と正解は公開していません(`bench/local/`)
- 確度の表記: 【実測】手元で計測した値 / 【公式】一次文書 / 【推測】確かめていないこと
- ここに載せるのは、条件を揃えて測り直した最新の値(2026-11-06〜08)です。それより前の計測(v1〜v12)は、問題の形や指示が cxxref に有利に偏っていたので、ここでは使いません。経緯と古い値は [design.md](design.md) にあります
- 条件の呼び名(A・G・P など)は design.md と同じです

## 0.5.10 の形(skill と hooks)の早見表(2026-11-13)

0.5.10 からプラグインは MCP サーバーを持たず、skill `cxxref` と hooks で索引を引きます(README の「skill と hooks」)。「どこで使われているか・変えると何に影響するか」の問いのときだけモデルが skill を読み、それ以外は従来どおり rg と view で進みます。この形を、rg だけと交互に流して測りました(下の「5. skill 版」)【実測】

| 場面 | 費用(rg だけとの比、95% 区間) | skill が読まれた回 | 正しさ |
|---|---|---|---|
| **C++ で呼び出し箇所を挙げる**(4 問) | **0.77 倍(0.65〜0.91)**。1 回目の時期も 0.77 倍(0.63〜0.92) | 20/20 | 回答に挙がった正解の行の割合は、rg だけ 0.40〜1.00、skill 版 0.79〜1.00 |
| **C++ で変更の影響を調べる**(2 問) | **0.53 倍・0.51 倍**(1 回目の時期 0.63・0.40) | 10/10 | 挙げたファイルの割合はどちらも 1.00 |
| C++ で呼び出し側を直す(3 問) | 0.90〜1.01 倍(rg だけと同じ) | 0/15 | 直すべき呼び出しはどちらも全部直した |
| C++ の説明・ログ・テストの追加(3 問) | 0.87〜1.07 倍 | 0/15 | 構文チェックの結果は同じ |
| C++ でないリポジトリ(9 問) | 1.01 倍(0.86〜1.19) | 0/27 | 同じ |
| 1 回の時間(C++ の 12 問) | 0.96 倍(0.85〜1.08) | | |

- 費用は、Copilot CLI が記録したトークンの内訳(キャッシュ読み・キャッシュ書き・出力)に Claude Haiku 5.5 の単価を掛けたものです。単価の比(キャッシュ読み 1 : 書き 12.5 : 出力 50)は、gpt-6-luna の AI credits を過去の 120 回から当てはめた比と同じなので、AI credits でも同じ比になると見ています【推測。gpt-6-luna では、この形を試しの 6 回しか流していない】
- 上乗せは、skill の説明文(約 100 トークン)と、索引のあるリポジトリでだけ hook が足す 1 文(約 60 トークン)です。1 回目のモデル呼び出しの入力は、C++ のリポジトリで約 270 トークン、C++ でないリポジトリで約 160 トークン増えました。0.5.9 までの形(MCP のツールの定義と使い方の指示)は、毎回約 2,100 トークンでした
- 呼び出し側を直す作業は、skill を読ませると費用が 1.06〜1.31 倍に増えた(1 回目の時期)ので、skill の対象から外しています。呼び出し箇所が分かっても、直すにはそのファイルを開くためです。この場面を改良する試み(`refs --context`)は、下の「5. skill 版」の最後
- **0.5.9 までの形(MCP 版)と同じ時期に交互に流した比較**(2026-11-16、下の「6.」)【実測】: C++ の 12 問をまとめると、skill 版は MCP 版の 0.91 倍(0.76〜1.05)で、差があるとは言えません。場面で向きが分かれます
  - 呼び出し箇所を挙げる問いは、MCP 版のほうが少ない(skill 版は入力トークンが MCP 版の 1.46 倍(1.19〜1.73)、費用は 1.05〜1.13 倍で区間は 1 を含む)。skill を読む・コマンドを実行する、の 2 段で往復が増えるためです
  - 影響の調査・直す作業を含む普段の作業は、skill 版のほうが少ない(MCP 版の 0.81 倍(0.67〜0.97))
  - 索引の無い C++ のリポジトリで「使っている箇所」を聞くと、skill 版は skill を読んでから rg に戻り、費用が rg だけの 1.26 倍になりました(3 回)
  - skill 版の preToolUse の hook は道具を呼ぶたびに走り、1 回 0.3 秒(PC の負荷が高いときは約 3 秒)かかります
- **呼び出し箇所で skill 版の往復が多かった原因を直しました**(0.5.10 の後の変更。2026-11-16、下の「7.」)【実測】。原因は、skill を読む 1 往復と、モデルが CLI の場所を書き間違えて最初のコマンドが断られる回(20 回中 7 回)でした。索引のあるリポジトリでは、sessionStart の hook が実行するコマンドを場所まで書いて渡すようにしたところ、呼び出し箇所を挙げる問いの費用は、直す前の skill 版の 0.82 倍(0.79〜0.86)、MCP 版の 0.85 倍(0.77〜0.94)、rg だけの 0.56 倍(0.48〜0.63)になりました。断られた回は 0 回です。索引を引かない 6 問(直す・説明・ログ・テスト)は、直す前の 1.01 倍(0.87〜1.18)で、差があるとは言えません
- **大きなコードベース(O3DE・UE5)でも、rg だけ・MCP 版・skill 版を比べました**(2026-11-16、下の「8.」)【実測】。O3DE の呼び出し箇所の 3 問で、skill 版の費用は rg だけの 0.29 倍(0.16〜0.64)、MCP 版は 0.69 倍(0.50〜1.00)。ただし skill 版は、索引の構成に入っていないテストのフォルダの呼び出しを、15 回中 12 回で全部は答えに入れませんでした(rg だけは 1 回、MCP 版は 4 回)。費用の少なさは、この確かめを省いた分を含みます。UE5 の影響の調査 2 問では、費用の差があるとは言えず、正解の行を挙げた割合は skill 版 0.94・0.99、MCP 版 0.86・0.95、rg だけ 0.67・0.45。skill 版は呼ぶたびに索引(12 GB)を開き直すので、1 回の時間が rg だけの 4.5 倍(138〜389 秒)でした
- **継承関係・基底呼び出し・virtual dispatch の可能性・条件コンパイル・テンプレートの実体化を調べる指示を問いに足すと、差が開きました**(2026-11-16、下の「9.」)【実測】。費用は、O3DE の 4 問で MCP 版が rg だけの 0.55 倍(0.45〜0.68)、skill 版が 0.40 倍(0.29〜0.54)、UE5 の 2 問で 0.56 倍(0.43〜0.66)と 0.34 倍(0.28〜0.40)。正解の行は 3 つの形ともほぼ全部挙げ、種類の付け方もほぼ同じでした。観点を書けば rg だけでも当たりますが、指示なしの 1.5〜5.1 倍の費用がかかります。cxxref の結果に無い情報(クラスの派生の関係、受け手の型、実体化の引数)と、足せるかの試作も 9 に書きました
- **skill 版が、索引の構成に入らないファイル(テスト、別のプラットフォーム)の一致も確かめて答えるように、hook の文と skill の本文を直しました**(2026-11-17、下の「10.」)【実測】。O3DE でテストのフォルダの呼び出しを全部挙げた回は、15 回中 1 回 → 14 回。費用は増えます(O3DE の呼び出し箇所で直す前の 2.85 倍(1.41〜4.44)、コードベース A の呼び出し箇所で 1.22 倍(1.10〜1.37))。直した後の O3DE の呼び出し箇所は、rg だけの 0.78 倍(0.56〜1.24)、MCP 版の 1.13 倍(0.89〜1.43)で、どちらとも差があるとは言えません。上の表と「7.」「8.」「9.」の skill 版の値は、直す前のものです
- この表の「費用」は、続けて流した計測での値です。新しいセッションの 1 回目の呼び出しが、前の回の書いた前置きをキャッシュから読めるので、間を空けて始めるセッションより固定の費用が小さく出ます。その分を戻すと、比は 1 に寄ります(2026-11-16 の計測で、呼び出し箇所の skill 版は 0.70 倍 → 0.79 倍)

## 共通の条件

- エージェント: GitHub Copilot CLI(O3DE は 1.0.105、ほかは 1.0.107)。`copilot -p` で 1 問ずつ、毎回新しいセッション
- PC: Windows 11、AMD Ryzen 9 9950X3D(16 コア・論理 32)、メモリ 64 GB
- モデル: gpt-6-luna(Copilot の AI credits。1 AI credit = $0.01【公式: GitHub Docs の billing】)と、Claude Haiku 5.5(Copilot CLI から Anthropic API を直接使う BYOK。従量課金)。どちらも小さく安いモデルで、強いモデルでは測っていません
- 作業フォルダは、毎回同じ状態に戻した写しです(git で戻すか、指紋で確かめる)
- **入力トークン**は、モデルを呼ぶたびに送った入力の合計です。Copilot CLI はモデルを呼ぶたびにそれまでの文脈を全部送り直すので、呼ぶ回数とツールの結果の大きさで決まります。プロンプトのキャッシュから読んだ分も含むので、費用の差は入力トークンの差より小さくなります(AI credits の列を参照)
- **比**(3・4): 問題ごとに、各条件の回の入力の平均どうしの比を出し、それを問題をまたいでまとめたものです。主に幾何平均を載せ、事前の計画で主な指標にした中央値も並べます。括弧の中は 95% の bootstrap 信頼区間で、問題を引き直し、選んだ問題の中で回も引き直したものです(`bench/ratio13.py`)
- **時期による揺れ**: 同じ問題・同じ条件でも、日によって入力が 2〜3 割変わることがありました。そのため、比べるのは同じ時期に交互に流した回どうしだけです

## 1. 呼び出し箇所を挙げる問題(コードベース A、v13 段階 3)

C++ のゲームエンジンコードベース A(367 TU)で、関数の呼び出し箇所を挙げさせました。cxxref のほかに、C++ の参照を引ける MCP サーバー 5 つと比べています。

### 問題文(名前を伏せたほかは、そのまま)

| 問題 | 問題文 | 正解の数 |
|---|---|---|
| T1 | このフォルダは C++ のゲームエンジンコードベース A のソースです。`a::reflection::ClassInfo` のメンバー関数 `GetType()` を呼び出している箇所をすべて挙げてください。他のクラスの `GetType()` の呼び出しは含めません。 | 9 |
| T2 | このフォルダは C++ のゲームエンジンコードベース A のソースです。`a::JobSystem::Initialize` を呼び出している箇所をすべて挙げてください(定義・宣言は含めません)。 | 15 |
| T3 | このフォルダは C++ のゲームエンジンコードベース A のソースです。`a::io::File::Read` を呼び出している箇所をすべて挙げてください(定義・宣言は含めません)。 | 3 |
| T4 | このフォルダは C++ のゲームエンジンコードベース A のソースです。`a::detail::IDelegateBase::Reset` を呼び出している箇所をすべて挙げてください。呼び出し先が `IDelegateBase::Reset` であるものが対象で、どの関数の中に書かれているかは問いません。派生クラスで定義された同名の関数 `Reset` を呼んでいる箇所は含めません。定義・宣言も含めません。 | 4 |

問題文の後に、回答の書式([bench/answer-format.md](../bench/answer-format.md))を付けました。問題と正解は公開していません(`bench/local/tasks-a.json`)。T1 は、`/* */` のコメントの中に同じ形の行が 2 つあり、rg で拾うと誤答になる問題です。T4 の呼び出しは、すべて 1 つのヘッダー(`delegate.h`)の中にあります。

この 4 問は、cxxref を作りながら私たちが選んだもので、rg の苦手な形(同じ名前が多い、コメント、テンプレート)に寄っています。cxxref に有利な問題だと考えてください。

- 費用: Haiku は BYOK(従量課金)で、この資料では費用を並べていません。キャッシュの分は安いので、費用の差は入力トークンの差より小さくなります

### 動きの例

モデルを呼ぶ 1 回ごとに、使った道具を 1 行に並べています。`bench/trace13.py` で記録から出し、同じファイルが続くところを「×N」にまとめ、長い区間は(…)で要約しました。道具を使わなかった呼び出し(最後に答えを書く回など)は行に出ません。対象は各問の 1 回目です。

```
T1 を A(rg だけ)で: 27 秒
  1  grep(GetType\s*\()
  2  grep((class_info|_class_info|base|from|dat...) ✗
  3  view(world.cpp) · view(world_legacy.cpp) ×4 · view(database.cpp) ×3 · view(socket_stream_reader.cpp)
     · view(editor_remote_server.cpp) · view(remote_system.cpp) ×3
  4  view(socket_stream_utility.cpp) ×2 · view(socket_stream_writer.cpp)

T1 を G(cxxref)で: 38 秒
  1  refs(a::reflection::ClassInfo::GetType)
  2  check(11 行) · view(remote_system.cpp)
  3  view(world_legacy.cpp)

T1 を M(clangd-mcp)で: 16 秒
  1  clangd-mcp-find_references · clangd-mcp-find_symbol
  2  view(database.cpp) ×2
  3  view(editor_remote_server.cpp) · view(socket_stream_reader.cpp) · view(world.cpp) · view(world_legacy.cpp)
```

rg だけでは、`GetType(` に一致した行がどのクラスの関数かを決めるため、ファイルを次々に開きます。cxxref は、clang が解決した呼び出しと、索引に入らない一致の理由(「コメントの中」など)を 1 回で返すので、開くファイルが減ります。

```
T4 を A(rg だけ)で: 入力 29,816、15 秒(3 回ともほぼ同じ)
  1  grep(\bReset\s*\() · grep(IDelegateBase)
  2  view(delegate.h)

T4 を G(cxxref)で: 入力 80,773、47 秒(3 回のうち 2 回がこの形。残りの 1 回は refs だけで 16,500)
  1  refs(a::detail::IDelegateBase::Reset)
  2  grep(Base\s*=|using Base|class .*Delegate|...) · check(4 行)
  3  view(delegate.h) ×3
  4  grep(using Base|void Reset|class IDelegate...)
  5  view(delegate.h)
```

T4 のように答えが 1 つのファイルにまとまっているときは、rg だけのほうが安く済みます。

```
# C++ 参照の検索(cxxref)

C++ のリポジトリでは、clang(libtooling)で全 TU を解析した参照索引(リポジトリのルートの `.index`)を、MCP サーバー `code-ref-index` のツールで引けます。

- 使う場面: C++ の関数・型・変数が「どこで使われているか・どこから呼ばれているか」を知る必要があるとき(引数を変える前の呼び出し元の洗い出し、変更の影響の調査、使っている箇所の質問)。このときは、ソースを grep する前に `refs` を呼びます
- 使わない場面: ファイルや関数の説明、場所の分かっている箇所の修正、ログやテストの追加など、使われている場所の一覧が要らない作業。C++ でないリポジトリ
- `refs`(引数 `name` は修飾名か、その末尾)は、1 回で次を返します。各行には、ファイルと行、その行の本文が付きます
  - `calls`: clang が解決した呼び出し。どの関数の中に書かれているか(`[in ...]`)付き。そのまま答えに使えます。同じ名前を rg でソースから取り直して確かめる必要はありません
  - `other references`: 関数ポインターの取得、テンプレート引数などの呼び出し以外の参照
  - `definitions and declarations`: 定義と宣言
  - `unresolved template calls (dep)`: テンプレート内で解決先が決まらない同名の呼び出し。注記とソース行から、呼び出し先を自分で判断してください
  - `text matches ... not in the index`: ソースの同名の一致のうち、索引に無いものとその理由(コメント内・無効な `#if`・マクロ定義・文字列・解析されていないファイル)。「コメント内」とされた一致は答えに含めません
- 呼び出し側を直すときは、`calls` の行の前後だけを開いて直します。直した後の確かめに `refs` を呼び直さないでください(直後は索引の作り直しが裏で走り、結果は前の索引の行を当て直したものです)。確かめは rg で足ります
- `refs` と `check` の引数 `root` には、作業中のフォルダの絶対パスを渡してください(サーバーはプラグインの場所で動くことがあります)
- `check`(引数 `locations` は `path:line` の配列)は、その行が索引でどう扱われているかを返します。rg などで見つけた行を答えに入れるか迷ったときに使います
- 索引が無い(`index not found`)と返ってきたら、そのリポジトリではふだんどおり rg などで探してください。索引の作り方は返ってきたメッセージにあります。作るのは時間がかかるので、作るかどうかはユーザーに確かめてください
```

v0.5.1 の rule は「C++ の呼び出し箇所・参照・定義を探すときは、grep の前にまず `refs`」とだけ書いていて、使わない場面と、直した後に呼び直さないことは書いていませんでした。

- **受け手で動く関数が決まる呼び出しの印と、受け手のクラスの行**(`CXXMethodDecl::getDevirtualizedMethod`・`Expr::getBestDynamicClassType`): 値の変数・`final` のクラス越しの呼び出しは決まる側、基底や中間のクラスの参照・ポインタ越しは決まらない側に分かれ、受け手のクラス(中間のクラスなら、そのクラス)が出ました
- **実体化の引数つきの呼び出し元の行**: `FreeList::Frag` ← `Sub<FreeList>::Frag`、`Alloc::Frag` ← `Sub<Pool>::Frag` の形で、実体化ごとの解決先が出ました
- 確かめたのは、30 行の小さな例 1 つです。O3DE の 40 TU を今の ltidx と試作で索引にすると、行は 17% 増(198,013 → 231,987)、大きさは 28% 増(37.9 MB → 48.5 MB)で、増えた行の 9 割は実体化の行でした(基底 601、受け手 1,671、実体化 31,702)。限定名の無い仮想関数の呼び出し 2,576 のうち、動く関数が 1 つに決まるものは 18 でした。解析の時間は同じ(34 秒)です
- 問い合わせの側(ltq が結果にどう出すか)は作っていません。出し方によって結果が大きくなり、費用が増えることがあります(2 の O2、5 の `--context`)。入れるなら、この 6 問で測り直します

### 限界

- O3DE 4 問 × 5 回、UE5 2 問 × 3 回、Claude Haiku 5.5 だけです
- 新しい 2 問(S-OV1・S-OV2)は、5 つの観点が 1 つの名前に揃う関数を、私たちが rg で探して選びました。乱数で選んだ問題ではありません
- どの問題にも、基底呼び出し・条件コンパイル・テンプレートが全部あるわけではありません(基底呼び出しは UE5 の 2 問だけ、テンプレートの中の行は S-OV2 の 1 行だけ)
- 種類の採点は、回答の `[...]` の中の語で決めています。値の変数越しの呼び出しは call でも virtual-call でも正解にしました。UE5 の限定名の無い呼び出しは、受け手を 1 行ずつは確かめていません(どちらでも正解)
- テストのフォルダの行は、索引を作った構成に入っていないので、inactive と付けても誤りにしていません
